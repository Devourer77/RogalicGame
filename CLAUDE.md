# Правила работы над игрой

## О проекте
- Пошаговый карточный рогалик в фэнтези-сеттинге: тактика на сетке, заклинания тянутся из колоды.
- Игра в 3D (3D-поле и персонажи, интерфейс карт — 2D поверх).
- Делает один человек (Рома), платформа — PC, монетизации нет.
- Движок: Godot 4.7, язык — GDScript. Синтаксис Godot 3 не использовать.

## Общение
- Отвечать на русском.
- Рома новичок в геймдеве и программировании: объяснять, что делает код и зачем, простыми словами. Новый термин — коротко пояснить при первом упоминании.
- Указывать, где в редакторе Godot что нажимать (какой узел, вкладка, куда прикрепить скрипт).
- Если задача неясна или есть несколько разумных вариантов — сначала коротко уточнить.
- Честно говорить, если идея усложнит проект или решение плохое, и предлагать более простой путь.

## Код
- Комментарии в коде — на русском. Имена переменных, функций, классов — на английском.
- Стиль GDScript по официальному гайду: snake_case для переменных и функций, PascalCase для классов, UPPER_CASE для констант. Отступы — табами.
- Всегда указывать типы (`var hp: int = 10`, `func deal_damage(amount: int) -> void`).
- Маленькие шаги: одна правка — одна проверяемая вещь. После правки объяснить, как проверить результат.
- Без преждевременных оптимизаций. Простое и понятное решение важнее «правильной» архитектуры на вырост.

## 3D
- Логика сетки отдельно от 3D-сцены: клетка — это `Vector2i`, позиция в мире считается функцией `Board.grid_to_world()`. Не определять клетку по физическим позициям объектов.
- Выбор клетки мышью — через raycast из камеры.
- Камера — фиксированный наклонный вид с поворотом и зумом.
- Интерфейс (рука карт, HP, кнопки) — узлы Control в CanvasLayer поверх 3D.
- Модели — glTF (`.glb`). Пока нет арта — простые формы (кубы, капсулы) как заглушки.
- Анимации — через Tween/AnimationPlayer; логика хода ждёт окончания анимации через сигнал.

## Архитектура
- Данные отдельно от логики: карты, заклинания, враги — Resource (`.tres`).
- Логика боя не зависит от отображения — 3D-сцена только показывает состояние.
- Связь между системами — через сигналы, а не прямые ссылки на чужие узлы.
- Глобальное состояние (забег, настройки) — autoload-синглтоны, без злоупотребления.
- Случайность — один общий генератор с сидом, чтобы забеги можно было воспроизвести.
- Папки: `scenes/`, `scripts/`, `resources/`, `assets/` (models, textures, sounds), `ui/`.

## Процесс
- Сначала играбельный прототип на заглушках (сетка, ход, одна карта, один враг), потом расширение и арт.
- Не переписывать работающий код без причины; рефакторинг — с объяснением зачем.
- При ошибках просить текст из окна Output/Debugger и разбирать по шагам.
